## 阶段3：每组固定操作顺序

`方块桌上摆位 → 手动夹紧并静止采B → 放开且确认原位 → 按组授权原轨迹回观测 → SEARCH前停止 → 静止采A → 当组质量/激励检查 → Git记录`

1. **夹持B**：操作者在有支撑的既有手动流程中摆到实际两指夹紧状态，方块留在桌面，不进行抬升。不能强行扳使能关节；代理不替操作者自动失能或盲闭爪。静止至少3秒，采至少30个新鲜SDK样本（当前工具默认6秒）；保存真实q/速度/使能/开口、5—10张原RGB及完整FK/模型版本。
2. **接触语义**：开口接近方块宽度是交叉检查，不是接触证明，更不直接确定轴向夹深。保存操作者接触/中心定义确认；斜夹、指垫会使读数不同，不硬要求恰好29mm。
3. **释放**：操作者打开夹爪，方块不移位/翻转。若被带动，保留失败记录，重新采同组，不虚填“未移动”。不可夹着方块返回观测。
4. **回观测**：只在当组明确授权后执行已有“当前姿态→观测”轨迹，SEARCH前停止。以真实轨迹状态和反馈确认到位；历史30秒客户端超时但46.2秒轨迹继续的现象不能触发重复发起。不是六轴绝对零点复位。
5. **观测A**：目标采60组原RGB/整幅原生uint16深度，保留坏帧，至少20高支撑有效帧用于相机中心估计；保存逐帧同戳深度Info K/D/R/P、编码/单位/frame、整数纳秒戳、同时间真实关节与静止统计，以及独立彩色内参与D→C资料。
6. **当组检查**：只用真实表面点和明确面/法向推断几何中心；不填补缺失深度，不拿背景代替方块。核对原位、接触、夹深一致性、同中心定义、时间/源文件/哈希。新增组进入累积可辨识性检查，早发现需要不同倾角，不等六组全采完才发现退化。
7. **记录/共享**：有限原始数据、manifest、逐帧统计、FK与参数快照进入规范仓库，按组限定提交并准备GitHub交付。采集时长和容量有上限，定期查看空间；不删除新证据。Git认证问题和物理采集问题分别记录，不反复尝试已失败push。

同阶段连续两次实机会话无新增有效证据就停止该实测并报告；仍可继续有意义离线工作。不是通过无限加生产门或小补丁来消耗现场会话。

## 阶段4—6：如何解算与采用

使用同一物理几何中心：

`T_B_G_obs · X_G_D · [p_D_center;1] = T_B_G_grip · [c_G_center;1]`

`B=base_link`，`G=gripper_base`，`D=depth optical`。报告安装变换 `X_G_D` 和恒定工具内中心 `c_G_center`，明确哪些已知/联合估计。训练五组，预留第六组不参与参数选择；另做留一诊断、基座xyz误差、秩/零空间/条件数、尺寸/夹深/噪声敏感性及旧外参对照。小训练残差不自动等于真实准确；讨论中的5—15mm容忍度不是批准放宽生产要求。

用户审阅后才采用。部署时必须按实际安装TF的父/子frame组合；例如实际挂载子frame若为camera_link，则 `X_G_camera_link = X_G_D · inverse(T_camera_link_D)`，不能直接把depth-optical解写成camera_link安装值。FK/TCP的实际中心若要变化，单独列范围并获批，不把未知夹持偏移偷偷塞到相机平移。备份原版本和哈希，记录构建/安装一致性；未获实体许可不因部署成功开始运动。
