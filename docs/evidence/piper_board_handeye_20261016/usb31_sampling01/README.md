## 本轮经过：失败也保留，不循环同条件运动

1. `wrapper_preflight/`：首10秒被动SDK新鲜、q波动0但有短速度脉冲，我复用的包装器额外要求完整SDK速度静止而提前结束，未启动控制。此门不是原已批准板采样器的准入；后续只去除包装器重复门，不改原SDK summarize或原采样器实时反馈／3秒q稳定／MoveIt／adapter规则。原SDK失败不改成成功；完整新会话前SDK4秒rc2／无合格子窗也照存，末SDK4秒rc0。
2. `full30/`：原30内部点会话采到7fit，第577帧后ID13靠近左夹指区域，准确BGR→gray回放前后向误差0.812px>原0.5，按原规则软件停机；5534命令、13轨迹，未夹爪／硬件失能。本会话不混入最终10组。
3. `return/`：从真实停止q，只沿同一原MoveIt／adapter函数返回该会话实际起点，完整返回且3秒q稳定。不是重做J4验证或无故再跑观测；返回目标是原起点，未强迫名义零位。
4. `seed_only/`：仅新采集副本把首帧选点限制在像素ROI `[110,95,175,165]`，远离实测夹指干扰，首帧选点不足9而在arm前结束。准确BGR→gray对同一原PNG重现3×7子网格／ROI0点；`imread(gray)`只差1灰度、38793像素不同，却给8×7／18点。早期非逐位一致的灰度诊断仍保留，不能拿其结果反证在线失败；[准确灰度审计](full_ROI/exact_gray_audit.json)纠正此区别。
5. `full_ROI/`：只补采集初始化，在原18秒就绪期限内拒绝不足9点的初始候选并记坐标／前5张原图；**固定身份建立前、arm前**才允许等待。身份建立后原0.5px／6px／800ms限制完全不变，不重编号。ROI18点对旧577段准确灰度回放全部通过。本次实际首候选即合格、0初始拒绝，连续842帧无身份丢失，原18往返与10组完成。所有原控制函数AST及原launch字节不变；仅picture采集初始化和运行路径／metadata变更，不是生产控制修改。
