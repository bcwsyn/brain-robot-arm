## 官方事实与本项目方案分开

- [OpenCV官方findChessboardCornersSB说明](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)：LARGER/meta接口支持标定板大于相机视野；若要跨图保持一致坐标，官方提到可用marker。**该接口不会替无标记普通棋盘格自动建立跨姿态物理ID**。本机4.5.4实际已有该接口，上一轮63点来自该接口；不要求升级OpenCV或换板。
- [OpenCV官方calibrateHandEye说明](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)：输入各姿态gripper→base与target→camera，输出camera→gripper。需要同一个固定标定目标坐标系，不要求原点一定在整板左上角；一个姿态不能求完整手眼。
- **本项目拟议**：从第一张实际原始图中的可见子网格选一个角点定义任意局部原点，已知格距32mm，保存固定点ID及局部物理坐标；以后只传播相同物理点的ID。整板照片中的全局行列不是这个方案的前提，但不是每帧任意重选/重置原点。板必须在整个多姿态会话保持固定。
- 几何原因：若所有姿态的target→camera都右乘同一个固定坐标变换Q，B_i Q (B_j Q)^−1=B_i B_j^−1；选择不同但固定的板原点不改变相对运动。若每帧原点不同Q_i，则不成立，不能用于手眼。
