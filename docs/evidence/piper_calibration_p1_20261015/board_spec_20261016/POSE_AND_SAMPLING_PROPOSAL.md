## 1. 位姿计算已完成到什么程度

[脚本](board_pose_offline.py)、[原始数值结果](board_pose_offline_result.json)、[7项测试](test_board_pose_offline.py)、[JUnit](board_pose_offline_junit.xml)。复用原五320×240 RGB、63个固定ID、原工厂值和实际FK，不重检测/重编号，不使用聊天截图作为标定像素，不依赖深度。

局部物点采用9×7可见候选的原排序、格距32mm、z=0。局部原点是首帧固定角点ID0，不是整板左上角；前提是此排列确实代表同一平面等距物理网格，该前提没有由低残差自动证明。

- OpenCV4.5.4 `solvePnPGeneric(...IPPE)`返回两平面候选，原IPPE矩阵/残差及各自LM精化矩阵均保留，未丢弃第二分支；本批精化后两分支收敛到几乎相同解，**不是独立证明真实分支**。
- 基线只复现已存的endpoint缩放K和报告CameraInfo零畸变，五帧精化RMS1.805727—1.811892px；首帧局部原点C系约[-155.548,-25.817,504.901]mm。所有物点z为正。此值是所选内参/平面/格距假设下的离线板位姿，不能当真实测距或相机安装位置。
- 最低残差分支的静止平移峰峰约[0.284743,0.030430,0.068078]mm，**仅同姿态重复性，不是绝对精度**。之前任意单应RMS约0.85px与本次受刚体/正方格约束PnP的约1.81px不是同一指标；不能混称变差或据此断言外参/板不平/内参哪一个有错。
- 初帧额外保留4种敏感性解释：endpoint/精确0.5缩放 × 报告零D/已存driver重排D，RMS约1.801—1.935px、原点平移相对基线最多4.216mm。它们只是对比，不据最小残差自动选新的K/D。raw_factory_D仍原样存，不猜另一种系数顺序，不改生产或查询设备setter。
- 七项合成测试覆盖：已知无畸变/有畸变位姿恢复、固定原点偏移等价、点数/对应维度/非有限/退化几何拒绝。它们证明函数数值与方向约定，不证明当前相机工厂K/D或板实际32mm准确。

官方依据：[OpenCV PnP](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)规定输出目标→相机，光学轴x右/y下/z前，IPPE用于共面点，Generic可保留多解。本机实际运行4.5.4，无升级或新依赖。

## 2. 坐标链与原始记录

`p_C = T_C_B * p_B`，C为**camera_color_optical_frame**，B为固定局部板系；原六轴实际q及RGB/反馈整数源戳逐帧保留，时间配对不是硬件同步。基座→夹持基座使用原便携包已保存的实际FK，不拿指尖/指缝视觉中心当同一坐标。

独立加载原部署模型重现了归档起点FK，URDF SHA为`0b41516e87e9bafd2a1e9b2821666ac1f24e5641131b8062134520aae0326d82`。新板采样若获准，最终输入为每姿态`T_base_gripper_base`和`T_C_B`，输出`T_gripper_base_C`，**不是**直接输出原TF中的camera_link或深度镜头。今后经报告批准部署时转换关系应为：

`T_gripper_depth = T_gripper_color * T_color_depth`

`T_gripper_camera_link = T_gripper_depth * inverse(T_camera_link_depth)`

其中D→C工厂变换和camera_link←depth_optical原变换来源已在原包，不丢掉镜头约30mm横向基线。当前不执行这些TF写入；相机手眼也不自动标定实际指尖/TCP，后续开环验证仍需检验夹持参考。

## 4. 如批准采用板路线，执行顺序

1. 先只读更新当天实际q/使能/原始RGB，确认板固定/存在，并重新建立本次连续会话固定物理ID。历史局部ID不跨隔夜自动续用；重新定义一次会话原点可以，但一个会话内不能逐帧重置。
2. 按当前实测起点重新生成上述偏移候选，由原MoveIt/适配器原限位/碰撞/反馈规则逐段检查。保持原夹爪开口，不搜索/抓取/复位/硬件失能。不能通过的候选只报告实际原因，不改生产门来凑数。
3. 连续保存有界原RGB跟踪信息；到每个姿态停稳后保存原始RGB、角点ID/观测值、K/D来源、同时间真实关节/源戳/FK及所有位姿候选，沿用原至少3秒/30反馈的静止记录，不发明同帧彩色CameraInfo。已存彩色K是工厂640查询，并非每帧RGB CameraInfo；320映射/畸变解释须明确，不伪造已知。
4. 首次新方向先核对实际连续ID/视野，再继续剩余候选；身份丢失时不把新局部原点当旧点续拟合。记录丢失不自动部署任何变换。
5. 本提案为**9拟合姿态+1独立验证姿态**；原方块5拟合+1留出数据全部保留作独立物理参照，不自动混入或改名凑新批次。路线/样本协议变更须用户明确批准后才执行，不将本轮“好的”视为已经批准多姿态。
6. 得到真实多姿态后才调用官方手眼求解，报告基座板位姿一致性、留出误差、K/D敏感性和与原TF差值。手摆/模型误差验收10mm原口径作为讨论基线，但具体板路线指标需确认。报告批准前不写TF、不恢复靠近算法修改；之后再按原入口准备开环抓取验证。
