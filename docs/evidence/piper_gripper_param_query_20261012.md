# 夹爪量程只读查询（2026-10-12）

起点提交 `5a33e3f`。用户确认继续后，本轮只发送官方 V2 参数查询 `0x477`，不调用 SDK 控制接口，不写参数，不使能，不发送 `0x159` 夹爪目标，不发送六轴目标，不写零点。

## 实测

- 查询报文：CAN ID `0x477`，数据 `04 00 00 00 03 00 00 00`。字段含义为 `param_enquiry=0x04`（查询夹爪/示教器参数），其余设置字段保持无效。
- 设备回复一次 `0x47E`：原始数据 `64 64 ff 00 00 00 00 00`。
- 按本机 SDK V2 解析：`teaching_range_per=100%`、`max_range_config=100 mm`、`teaching_friction=255`。前两项是有效硬件配置；255 在该固件回复中作为未定义/保留值记录，不据此改参数。
- 查询前后六轴 0.001° 原始反馈：`[-11882,108351,-71052,0,52082,0]`，逐轴变化全为 0。
- 查询期间夹爪 `0x3A7` 共361帧，位置均 `101900`（0.001 mm 单位）、状态均 `0x40`；没有 `0x159` 控制帧。
- 因此本轮明确排除“查询动作导致运动/夹爪动作”。实体开闭仍未验证，零点仍未写入。

## 事实与推断分开

官方 SDK 文档说明 `0x477/0x47E` 可查询夹爪参数，最大控制行程可为 70 或 100 mm；`GripperCtrl` 使用 0.001 mm。这个设备实际回复 100 mm，不能继续把小夹爪 70 mm 作为当前配置。

项目推断是：反馈位置 `101.9 mm` 高于设备报告的最大控制行程 `100 mm`，说明它是未解释的实体/固件位置语义矛盾；不能直接当作实际开口、最大张开或闭合位置，也不能用软件减去 1.9 mm 伪造校准。查询回显 `0x477` 本身不当作设备应答，只有 `0x47E` 被记录为回复。
