# 实机夹爪闭合链路验证（2026-10-12）

起点 `e5371f0`。用户确认实体夹爪内无障碍物并要求闭合。本轮沿现有适配器链路执行有界目标 `0.0 m`，不改代码、不写零点、不发送六轴目标、不失能机械臂。

## 结果

- `/enable_srv=true` 返回成功；此入口不注入夹爪目标。适配器接受第一次 `0.0 m` 请求并生成5帧；驱动日志确认4次 `GripperCtrl(angle=0, effort=1000)`：首帧 `0x03`、随后 `0x01`。适配器随后因一次反馈超时自动 disarm。
- 3秒只读复核：反馈600样本、199.66Hz、最大间隔11.23ms、末帧年龄0.03ms。重新 arm 后第三次请求生成5帧，驱动日志确认5次 `0x01`；第二次请求在 disarm 状态被拒绝。
- 两次有效请求前后六轴均为 `[-0.207269608,1.890074844,-1.239431088,0,0.908518408,0]` rad；夹爪 `0x3A7` 始终 position `101900`、status `0x40`，ROS 为 `0.1019 m`，没有闭合位移。
- 探针未收到 `0x159` 回显；官方 SDK 发送 socket 使用 `local_loopback=False`，故不以此否认 `GripperCtrl` 调用。适配器日志和驱动日志是软件链路证据，`0x3A7` 不变是实体结果。

## 结论与待批准修复

阻断已收敛为：目标进入驱动的 `GripperCtrl`，但实体位置没有响应。不能继续重复0 mm命令，也不能软件减去1.9 mm。当前驱动保持使能，适配器已 disarm。

官方 V2 示例采用 `0x02（失能并清错）→0x01（使能）` 后再发送目标；当前项目首个目标使用 `0x03`。建议只改一次性首个目标状态机：

```text
GripperCtrl(0, 1000, 0x02, 0)
GripperCtrl(0, 1000, 0x01, 0)
GripperCtrl(target, 1000, 0x01, 0)
```

保持适配器5帧、目标范围、六轴保持、反馈门和零点禁止规则不变；同步测试、构建、重新加载，再做一次单次实机验证。此项待用户批准后修改。
