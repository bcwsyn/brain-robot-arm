# 小球与圆柱体仿真验证及下一步研发规划

日期：2026-10-11。对象：当前 `simulation/` 工作区，来源为 `brain-robot-arm@6ebd0c53ca83`。依据：本机代码、运行日志及[整体机械臂研发规划](机械臂方向研发规划.md)，不采用上游旧电脑的验收结论。

> 2026-10-12 后续更新：第一步的控制交接与完整取放已实现，最新验收记录见[第一步开发与验收](第一步_单物品闭环开发与验收.md)。本文保留 2026-10-11 修复前的基线结果与后续规划。

> 2026-10-13 后续更新：经过[随机视觉取放阶段](第二步_随机视觉取放开发与验收.md)，独立物理模式的小球与圆柱体各 20 轮仿真取放通过，见[第三步物理抓取报告](第三步_物理抓取开发与验收.md)。历史基线结果不改写为新结论。

## 1. 先看结论

代码确实包含红色小球和红色圆柱体。圆柱体在代码中叫 `medicine_cup`，模型是实心圆柱的近似体，并不是完整的空心杯模型。

**构建和基础算法测试已经通过，但本机默认配置未能完成抓取。** 小球完成了识别、居中和移动到预抓取位姿，随后接近轨迹执行失败；圆柱体固定坐标取放在预抓取规划阶段失败，视觉流程则反复丢失目标并超时。小球冻结跟踪对照能进一步完成接近和夹爪闭合，但抬升仍失败。因此现在可以把它们作为待修复的研发基础，不能当作已验收的抓取程序。

另外，两种物品的重力都关闭，程序会把物品位置直接设为跟随夹爪的位置。因此即使后续演示抬起物品，也只能验收“流程演示”，不能据此计算申请书要求的真实抓取成功率。

## 2. 本次如何验证

仅构建 `simulation/`，未构建或修改 `real_robot/`，没有安装依赖，也没有连接 CAN、相机硬件或真实机械臂。

验证使用无窗口 Gazebo、MoveIt、虚拟关节控制器、虚拟腕部 RGB-D 相机及对应任务节点。采用独立的 `ROS_DOMAIN_ID=82`、仅本机 ROS 通信和独立 Gazebo 端口。运行阶段因沙箱禁止本机 socket，经授权在沙箱外执行。

与只查看终端文字不同，验证脚本还订阅 Gazebo 的 `/gazebo/model_states`，记录物品实际坐标。判据是：

- 固定圆柱体取放：任务完成、确实抬升至少 5 cm，并放到 `(0.40, 0.12, 0.05)` 附近，位置误差小于 3 cm。
- 视觉抓取：任务到达 `HOLDING`，且物品的实际高度相对初始位置增加至少 5 cm。
- 发生故障或超过 300 秒则不通过。上述数值是本次流程检查阈值，不是申请书已有承诺。

| 检查 | 结果 | 能证明什么 |
| --- | --- | --- |
| 7 个默认仿真包 `colcon build --symlink-install` | 通过 | 目前依赖可完成这些包的编译；不能保证所有运行插件可加载 |
| RGB-D 几何、抓取几何、视觉反馈、搜索、目标等待单元测试 | 39 个算法用例全部通过，5 个 CTest 测试目标通过 | 这些局部算法符合已有测试；不等于端到端抓取通过 |
| 圆柱体固定坐标取放 | 不通过 | 夹爪可以打开；默认预抓取位姿未找到有效轨迹 |
| 小球默认视觉抓取 | 不通过 | 识别、视觉居中、预抓取移动可运行；接近轨迹被拒绝 |
| 圆柱体默认视觉抓取 | 不通过，任务等待 300 秒后超时 | 已识别目标，但姿态调整后反复丢失目标，物品仍在原位 |
| 小球冻结跟踪对照 | 不通过，但推进到接近、闭合和几何接触检查 | 抬升轨迹仍因起点状态偏差被拒绝，没有达到 `HOLDING` |
| 重力、摩擦、接触驱动的抓取 | 未通过验收，本次未执行独立物理模式 | 当前模型及跟随机制不满足物理抓取验收条件 |

`colcon test-result` 汇总的 44 项包含 5 个 CTest 目标和其中 39 个 GTest 用例，不应写成 44 个独立算法用例。

### 2.1 圆柱体固定坐标取放

入口：[pick_place.launch.py](../simulation/src/brain_robot_pick_place/launch/pick_place.launch.py)。它直接使用场景已知坐标，不依靠视觉识别。

物品初始位置是 `(0.400, -0.120, 0.050)` m，默认顶抓预抓取目标的夹爪基座位置约为 `(0.400, -0.120, 0.306)` m。夹爪打开成功，之后 OMPL 报告 `Unable to sample any valid states for goal tree`，任务节点退出码为 7。

这说明**本次未获得有效的目标关节状态**。具体是逆运动学无解、限位、碰撞还是姿态约束的问题，需要分项诊断；不能简单称为“机械臂一定够不到”，也不能关闭碰撞检查来宣称成功。

### 2.2 小球默认视觉抓取

入口：[ball_visual_search.launch.py](../simulation/src/brain_robot_ball_pick/launch/ball_visual_search.launch.py)。实际经历了：

```text
PREPARE → SEARCH → ALIGN → GRASP_READY
→ 打开夹爪 → 候选斜侧抓规划 → 预抓取执行成功
→ 接近轨迹被拒绝 → FAULT_DIAGONAL_SIDE_APPROACH_FAILED
```

约 86 秒时停止。小球实际位置仍为 `(0.400, -0.120, 0.0175)` m，没有抬起。MoveIt 的拒绝原因是轨迹起点偏离当前关节状态，日志中 J1 为：

```text
allowed_start_tolerance = 0.01 rad
expected = -0.915373 rad
current  = -0.480883 rad
```

偏差约 0.43449 rad，即约 24.9°，远大于允许误差。失败前视觉控制重新进入 `ALIGN`，恢复视觉微调。这是**两个控制源同时争用机械臂**的强线索，后续应结合冻结跟踪对照、关节命令与执行反馈验证原因。不要通过放宽起点误差容忍度绕过拒绝。

### 2.3 圆柱体视觉抓取

入口：[visual_search.launch.py](../simulation/src/brain_robot_pick_place/launch/visual_search.launch.py)。目前观察到 HSV 检测能够找到圆柱体，但执行 J2/J3/J5 姿态调整时反复丢失目标：

```text
ALIGN → LEVEL_ALIGN → LEVEL_RECOVERY → LOCAL_SEARCH → ALIGN → …
```

这与固定坐标程序的失败是两个不同问题：前者需要修正视野保持、姿态调整和状态超时；后者需要诊断目标位姿可行性。

任务等待上限为 300 秒，加上启动准备，本次约 306 秒结束。圆柱体实际位置仍为 `(0.400, -0.120, 0.050)` m。多次丢失目标都出现在 `LEVEL_ALIGN`，不能把多次重新识别视为多次成功抓取。

### 2.4 小球冻结跟踪对照

复制默认小球配置，仅增加 `visual_search_controller.freeze_grasp_tracking: true`。原默认配置未覆盖，C++ 抓取算法未改。对照配置见[ball_task_freeze_tracking.yaml](../simulation/validation/ball_task_freeze_tracking.yaml)。

首次对照在初始关节反馈还未到达时被拒绝；验证脚本补上有界握手等待后重新运行。有效对照约 143 秒时完成预抓取、接近、夹爪闭合，并通过几何中心距离检查（约 19 mm，小于 25 mm 阈值）。随后抬升 / 反向退出轨迹被拒绝，状态为 `FAULT_LIFT_FAILED_HOLDING_CUP`；状态名中的 CUP 是共用执行器的历史命名，此次对象是小球。

本次拒绝为 J5 起点偏差：期望 `-0.911367` rad，实际 `-0.924327` rad，差约 `0.01296` rad，大于 `0.01` rad 阈值。记录的最后物品高度约为 20.2 mm，初始为 17.5 mm，远未达到本次 50 mm 抬升条件；也未到达 `HOLDING`。

这个对照支持了控制权交接的重要性，但只有一个有效对照运行，规划采样也存在随机性，不能证明所有失败都由 Servo 导致。下一步还需测量上一段轨迹结束后的残余运动、反馈时间戳和笛卡尔轨迹起点，与稳定的实测状态一致后再执行。不能简单放大允许起点偏差。

### 2.5 启动与退出问题

首次保存截图因本机 Python 用户目录 NumPy 2 与 ROS `cv_bridge` 二进制不兼容导致验证脚本异常退出；已改用 Pillow 保存原始图像，并用 `python3 -s` 运行验证器，未改动系统包。另一次控制器并行加载造成 `gripper8_controller` 未激活；仿真 launch 已改为顺序加载，后续有效试验中四个控制器均为 active。

部分试验在发送结束信号后的 MoveIt / Servo 退出阶段出现异常堆栈，原日志保留；这不等于它们在运动中崩溃，但退出稳定性也应纳入后续回归。上述启动、验证器异常记录不用于计算抓取成功率。本次运行次数很少，只能用于定位问题，不能推算项目的统计成功率。

## 3. 为什么现有“抓取”不等于物理抓取

| 代码事实 | 含义 |
| --- | --- |
| 两种物品的 SDF 均有 `<gravity>false</gravity>` | 没有正常重力下的掉落、支撑和保持验证 |
| `ball_follow_node.py` / `cup_follow_node.py` 根据夹爪 TF 计算物品目标位姿 | 物品跟随是程序计算出来的，不是夹爪摩擦产生的 |
| `cup_pose_plugin.cpp` 使用 `SetWorldPose` 并将线速度、角速度归零 | Gazebo 中看到的物品运动被直接设定 |
| 小球启用了 `grasp_contact_check_enabled` | 此检查实际比较物品中心与假设抓取中心的距离，阈值为 25 mm；不是接触力传感器，也不证明两侧夹爪接触 |
| MoveIt 的 `attachObject` | 给规划器表示“物品随机械臂移动”，并不产生 Gazebo 中的物理夹持力 |

所以要分别统计“控制流程成功”“物理仿真抓取成功”“真机抓取成功”，各自使用自己的试验数据。

## 5. 下一步按什么顺序做

以下是建议研发任务，**本次尚未实现**。每一步都有明确输出与验收条件，前一步达到条件再进入下一步。

### 第一步：先得到一个可重复的单物品闭环

目标：把现在“能识别、能规划部分动作”推进到“同一个场景反复运行能拿起并放下”。先继续用 HSV，不训练神经网络。

需要做的具体工作：

1. **整理运行环境。** 当前 MoveIt 核心为 `2.5.10`，Pilz 为 `2.5.9`，后者依赖的 `.so.2.5.9` 不存在；CHOMP 缺少 `libchomp_motion_planner.so.2.5.10`。先确定一致的包版本与实际使用的规划管线。仿真当前主要使用 OMPL，这些额外插件的加载失败不能直接解释所有抓取失败。更改系统包前按项目规则另行批准；不创建冒充旧版本库的符号链接。
2. **建立一个机械臂命令的统一入口。** 搜索/居中时由 Servo 控制；执行抓取轨迹时暂停 Servo；轨迹完成或明确取消后再交回。现有冻结跟踪对照已推进到闭合阶段，下一步实现正式状态机仲裁，保留停止与数据失效检查；同时等待关节速度和位置稳定，用新鲜实测状态生成下一段轨迹，并在输出前复查起点。
3. **分离圆柱体的 IK、碰撞和姿态问题。** 用 `/compute_ik` 诊断不同抓取姿态；比较忽略碰撞的诊断结果与开启碰撞检查的规划结果。实际执行始终进行碰撞检查。若顶抓不可行，生成侧抓/斜侧抓候选，不凭感觉增加机械臂行程。
4. **修正视觉时序和恢复策略。** 对图像时间戳对应的 TF 做有界等待，采用 tf2 消息过滤 / 等待队列；不能直接换成任意最新 TF。圆柱体姿态调整过程中保存视野、减小角度步长；限制恢复次数和整段任务耗时，避免无限循环。
5. **检查候选抓取循环。** `DiagonalSidePointGraspAndLift()` 找到候选后只退出最内层循环，之后仍会搜索、覆盖候选；需要明确“找到即退出全部搜索”或“评分后选最优”的策略。评分可考虑 IK 成功、碰撞间距、关节位移、接近路径完整率和耗时。
6. **补齐释放和放置。** 小球默认流程停在 `HOLDING`，不代表完整取放。增加固定放置区、放下、松爪、退出和回待机；区分场景生成完成与抓取执行器准备完成的话题，避免多个节点用同一 ready 标志表达不同含义。

用到：FSM、KDL/现有 IK 求解器、RRTConnect、碰撞检查、笛卡尔路径、TF 时间同步、控制权仲裁。这里无需 YOLO、强化学习。

建议验收：球和圆柱体先各做 20 次预先规定位置的流程试验；保存每次最终位置、失败阶段和任务耗时；加入目标消失、停止请求、规划无解的失败用例。此时仍明确标记为跟随式流程验证。

### 第二步：把跟随演示变成物理抓取试验

目标：物品真的是被夹爪夹起来，松开会落下。

新增两个明确模式：`flow_demo` 保留旧演示；`physics_grasp` 开启物品重力，并关闭物品位姿强制设置 / 跟随机制。两者不能共用一个“成功率”口径。

先用球和圆柱体：检查桌面接触面、夹爪碰撞几何、物品质量与惯量、夹爪闭合速度/力限和摩擦参数。物品尺寸必须小于实际可用开口并留出余量，不能只看 URDF 关节行程。针对穿透、抖动、滑落分别调整接触求解与控制参数。

用到：刚体动力学、库仑摩擦、接触模型、夹爪位置 / 力限控制、双侧接触与物品保持判定。球和圆柱体先用几何抓取规则；复杂抓取网络不是这一阶段的前提。

建议验收：关闭跟随模式后，物品能在桌面稳定放置；两侧夹爪接触后抬升至少 5 cm、保持 3 秒、搬到固定区域并释放。故意偏离目标应失败，松爪应释放；传感接触成立和实际物品保持都要检查。先每种物品 20 次，再扩大样本；这些数值是建议门槛。

### 第三步：从一个红色目标扩展到多类别目标

目标：不依赖“只有一个红色东西”，而能选择指定物品。

先支持 3 类易抓样品，再扩展到申请书的 10 类以上。为每类确定真实样品、尺寸、材质、质量和夹持限制。收集不同位置、光照、背景与遮挡下的 RGB-D 数据，训练 / 测试按场景或采集批次隔离。

用到：**YOLOv8n 微调**输出类别、框和置信度；深度有效像素的中位数 / 鲁棒统计；针孔相机反投影；TF 坐标转换。必要时使用分割限定物体深度区域，避免把背景深度混进框内。多个同类目标可先用最近邻数据关联，稳定后再考虑跟踪算法。

三维表面点不是物体中心。球要补偿半径、圆柱体要估计轴线和高度；可用点云的 RANSAC 平面去桌面、球 / 圆柱拟合、PCA 主轴。这样才能把“看见的位置”变成“夹爪应夹的位置”。

建议输出：检测数据集、训练版本、独立测试集结果、定位误差表；识别误差与定位误差分别统计，不能用检测精度代替抓取成功率。

### 第四步：建立按物品类型选择的抓取规则库

输入类别、尺寸、位置 / 朝向，输出候选抓取位姿、夹爪开度、预抓距离、闭合限制、抬升方向和放置策略。

球采用半径与中心模型；圆柱体采用轴线和直径模型；盒体采用长宽高与主轴模型。规则先生成多个候选，用 IK、碰撞检测和路径可执行性筛选，再按路径长度、关节余量等排序。不要给所有类别套用同一组固定偏移量。

用到：几何模型、PCA / RANSAC、规则库、IK、候选评分、OMPL；接近阶段使用保持姿态的笛卡尔路径。再加入有限的视觉位置误差修正（PBVS）；已有图像居中只能作为其中一个环节。

建议验收：至少 3 类物品从识别到放置完整闭环，逐类记录结果；再扩展到 10 类以上。复杂非规则物品确有需求时，再比较抓取位姿网络，避免一开始就增加训练负担。

### 第五步：接入模拟人机指令，再接真实脑机输入

先用键盘 / 模拟消息复现：“头部姿态粗调 → 选择目标 → 抓取触发 → 停止”。统一任务接口并记录输入时间戳、置信度、有效期和任务编号，禁止重复触发并发抓取。

用到：IMU 四元数坐标变换、低通滤波、死区、限速；状态机进行手动控制与自主抓取仲裁。SSVEP 解码由脑机组提供，可先建立 CCA/FBCCA 基线；申请书中的 ACB-Net 要先核实具体论文和实现。EOG 检测使用阈值 / 分类与去抖，机械臂模块负责执行停止请求和测量实际停止响应。

建议验收：模拟输入先通过丢包、过期消息、重复触发及各运动阶段停止试验；随后联调真实输入。脑电分类准确率和机械臂任务成功率分别报告。

### 第六步：校准真机与抓取反馈

这一步进入独立的 `real_robot/` 研发阶段，需要单独授权和现场监督，不在本次运行范围内。

确定相机实际型号、安装刚性和深度质量，测量相机内参，使用棋盘格 / ArUco 与眼在手上手眼标定（如 Tsai–Lenz / Park 方法）得到可靠外参；验证关节零位、末端偏移、夹爪开度单位、限位及命令反馈。

先做不接触物品的定位与低速运动验证，再做单物品抓取；加入夹爪状态和物品保持反馈。确有可标定的力 / 力矩测量时再做 PI 力控、阻抗 / 导纳控制；只有电流或力度设定时，不能直接称为精确力闭环。

### 第七步：按申请书指标组织正式实验

申请书要求包含 10 类以上物品、抓取成功率至少 88%、桌面和床头两类场景、2 小时连续运行。应先固定协议：

- 每类物品的样品、位置范围、遮挡程度、重复次数、允许重试次数。
- “首次抓取成功”和“允许重试后的完整取放成功”分别统计。
- 识别、定位、规划、执行、保持、放置分别记录失败原因。
- 报告总成功率、逐类成功率、样本数与置信区间；一次成功演示不构成成功率。
- 连续运行记录资源占用、延迟、恢复次数和温度 / 通信异常，停止响应单列。

用到：试验设计、ROS bag / 结构化日志、统计分析与消融实验。场景扩展要逐步进行，人体附近任务另行设计与审批。

### 第八步：最后评估学习策略是否有必要

规则抓取稳定、已有足够演示数据后，才评估申请书提及的模仿学习 **BC** 和 **DDPG**。先做规则基线与 BC 对照，再在仿真中考虑 DDPG 优化有限的接近偏移或闭合参数，定义状态、动作范围和奖励。

学习策略仍须经过几何可行性、碰撞与限速检查；不能直接用无约束探索控制真机。没有超过基线的实验数据时，不把引入神经网络当成研发进度。

```bash
cd /home/young1x/robot_projects/piper_robot/simulation
source /opt/ros/humble/setup.bash
source install/setup.bash
python3 -s scripts/validate_sim_grasp.py ball --timeout 300 \
  --output validation/runs/ball-new-run
```

`--output` 必须使用未存在的目录，以免覆盖证据。其他任务为 `cup-known`、`cup-vision`；`--params-file` 可指定仿真对照配置。运行前确认没有其他同域测试，机器具备可用的相机渲染环境。本次无窗口 Gazebo 使用已有的 `DISPLAY=:0`，未证明在完全没有图形渲染环境的服务器上也能运行。
