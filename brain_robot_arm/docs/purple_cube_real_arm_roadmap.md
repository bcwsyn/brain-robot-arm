# 紫色方块真机抓取路线图

更新时间：2026-09-22

## 当前结论

当前视觉搜索、目标丢失后的最后路径重捕获和 `GRASP_READY` 状态已经存在，但实体机械臂尚未完成过一次成功抓取。因此当前首要目标不是继续叠加动态功能，而是先建立一个可重复验证的最小抓取闭环。

最近一次目标丢失测试显示：控制器进入 `LAST_PATH_REACQUIRE` 后，MoveIt 的 `RRTConnect` 连续报告 `Unable to solve the planning problem`，同时出现 `SEARCH_HOLD_PLANNING_SCENE_STALE`。这说明“规划失败后的恢复”与“点云/Octomap 场景质量”都需要单独处理，不能把停住误认为搜索正常结束。

## 当前阶段：粗略抓取（优先完成）

目标：先让一个已经确认处于工作空间内的紫色方块完成一次真实的“接近—闭爪—抬升”，暂不追求动态目标跟踪和完整避障。

### 任务清单

- [ ] 建立固定目标/已对齐目标的抓取测试入口，不依赖目标丢失重捕获。
- [ ] 确认 `GRASP_READY` 到抓取执行器的状态交接不会丢失。
- [ ] 确认夹爪在抓取开始时保持张开。
- [ ] 规划到可达的预抓取姿态，验证轨迹确实发送到 PiPER。
- [ ] 以短距离、低速接近目标，验证末端没有直接冲向目标或穿过桌面。
- [ ] 闭合夹爪并保持闭合，确认方块实际进入夹爪而不是空夹。
- [ ] 抬升一小段并保持，确认方块没有立即掉落。
- [ ] 每个阶段发布明确状态和失败原因：预抓取规划、接近、闭爪、抬升分别可区分。
- [ ] 在实体上记录一次成功和失败的关节位置、目标深度、夹爪开度与规划诊断，作为后续标定数据。

### 粗略抓取阶段的边界

本阶段先使用单一、可重复的抓取姿态和短接近距离；不加入“边对齐边抓取”、目标运动预测、颜色候选重识别、主动扫描和复杂动态重规划。碰撞检查不能被永久关闭，但在验证抓取链路时要能区分“抓取执行器故障”和“错误 Octomap 导致的规划失败”。

### 通过标准

在同一目标摆放位置重复运行至少三次，其中至少一次完成闭爪并抬升；失败时能明确归因到规划、执行反馈、目标深度、夹爪开度或实际夹取，而不是只显示一个通用的 `PLAN_FAILED`。

## 后续阶段：规划场景和自体过滤

### 1. 机器人自体过滤

- [ ] 检查 PiPER URDF 中连杆、夹爪和相机支架的 collision geometry。
- [ ] 检查相机光学坐标系到安装连杆的 TF 外参，以及点云时间戳与关节状态时间戳是否一致。
- [ ] 验证 MoveIt `PointCloudOctomapUpdater` 输出的过滤点云：机械臂和夹爪点应被移除，桌面和外部障碍应保留。
- [ ] 实测调整 `padding_scale` 与 `padding_offset`，不能凭经验无限增大。
- [ ] 必要时比较官方 `DepthImageOctomapUpdater`，评估其内置自过滤是否更适合当前 RGB-D 相机。

不要使用“在图像中长期不动的点就是夹爪”的规则。桌面、支架和固定障碍同样可能长期不动，且腕部相机运动会改变图像中的背景运动。自体过滤应依赖机器人模型、TF 和同步关节状态。

### 2. 固定环境建模

- [ ] 将桌面、电脑支架和相机支架分别表示为低复杂度的 box、plane 或 cylinder 碰撞体。
- [ ] 对已知桌面区域做平面/背景处理，避免把整张带噪声的桌面点云直接作为高密度障碍。
- [ ] 明确机器人连杆属于机器人模型，不作为世界障碍重复写入 Octomap。
- [ ] 确认实体启动时只创建当前 ROS 会话的临时环境模型，不写入永久场景。

### 3. 规划失败恢复

- [ ] 记录具体碰撞对和规划起始状态，区分自碰撞、Octomap 碰撞、关节不可达和规划超时。
- [ ] 连续规划失败达到阈值后，从 `LAST_PATH_REACQUIRE` 强制转入 `LOCAL_SEARCH`，不无限重试同一目标。
- [ ] 局部搜索失败后扩展到 `FULL_SEARCH`，而不是保持零速度但仍宣称正在搜索。
- [ ] 点云短暂过期时进入有限等待并重新获取场景；只有真正的 Servo 硬碰撞、CAN 故障或反馈超时才进入 `FAULT`。
- [ ] 评估多次规划尝试、规划时间和搜索步长，但不能用无限增大规划时间掩盖错误碰撞场景。

## 后续阶段：动态跟踪和闭环抓取

- [ ] 先完成基础抓取，再增加接近过程中的“一帧对齐、一帧抓取”闭环。
- [ ] 保存目标像素、深度和关节历史，使用目标运动方向预测短时重捕获。
- [ ] 目标丢失后，先沿最后可信轨迹有限重捕获，再进入局部搜索和全局搜索。
- [ ] 颜色候选只能触发重新识别，不能看到相近颜色就直接驱动机械臂对齐。
- [ ] 目标重新识别成功后才恢复对齐和抓取，不使用单帧颜色结果授权抓取。
- [ ] 在不同光照下收集误检和漏检样本，先调整颜色空间、深度质量门和几何约束；只有传统方法不足时再考虑训练模型。

## 验证顺序

1. 固定目标，验证抓取执行链路。
2. 粗略视觉对齐后，复用已验证的抓取模板。
3. 验证预抓取规划和短距离接近。
4. 验证自体过滤、桌面/支架模型和 Octomap 稳定性。
5. 修复规划失败后的搜索恢复。
6. 最后加入动态跟踪、目标重捕获和连续重规划。

每一阶段都必须记录：预期状态、实际状态、规划结果、关节反馈、目标深度、夹爪动作和失败原因。仿真成功、成功编译和实体抓取成功分别记录，不能互相替代。
