# PiPER 真机有限候选粗略抓取设计

日期：2026-09-22  
状态：已确认设计，待实施

## 目标

为实体 PiPER 的紫色方块建立第一次可重复的端到端粗略抓取闭环。视觉控制器已经将目标带到 `GRASP_READY` 后，抓取执行器不再只依赖一个固定夹爪姿态，而是在有限的候选抓取姿态中自动选择首个具有可行 IK、无碰撞规划和可执行轨迹的方案。

本设计的成功不是实现任意六轴姿态搜索，而是在当前标定、关节范围和桌面实验环境下，完成一次可诊断的“预抓取—短距离接近—闭爪—小幅抬升”。

## 已验证上下文

- 当前真实配置中 `grasp_lift_executor` 已接收 RGB-D 目标点、深度有效性、视觉状态和 PiPER 关节反馈。
- 当前按键 `2` 仅在 `GRASP_READY` 后请求抓取，真实夹爪通过 `/brain_robot_grasp/gripper_command` 发送开/合命令，真实手臂轨迹通过 `/brain_robot_grasp/arm_trajectory` 交给 `piper_jog_adapter`。
- 当前通用抓取路径保持当前夹爪姿态、从预抓取点逐步靠近；真实测试已出现 `ALIGNED_PREGRASP_PLAN_FAILED`。
- 当前 Octomap 可能包含机械臂、夹爪、桌面或支架的误障碍；其自过滤和固定环境建模是后续独立任务，不能把未经验证的地图直接当作唯一抓取策略依据。

## 不采用无限自由姿态搜索

不在第一版对连续的六维位姿空间进行随机采样。无限候选空间会同时放大 IK、碰撞、桌面净空、夹爪开口和执行失败的归因难度，也不利于实体调试。

第一版采用有限、可记录的候选集合：候选的接近方向和偏航有限，但最终实际采用哪个由 MoveIt 可行性决定。因此它不强制夹爪绝对水平或绝对竖直，同时保持失败可解释。

## 候选集合

以已通过深度质量门的方块三维中心为基础，构造下列候选。每个候选均包含一个预抓取位姿与一个抓取位姿；预抓取与抓取之间只允许短距离、低速接近。

1. `TOP_DOWN`：从方块上方接近。使用已有的顶部预抓取高度、抓取净空和偏航候选。
2. `DIAGONAL_LEFT`：从左前上方斜向接近。沿候选方向保留预抓取退距和垂直净空。
3. `DIAGONAL_RIGHT`：从右前上方斜向接近。参数与左侧对称。

候选顺序不是硬编码的抓取偏好，而是按以下代价排序：

1. 当前关节姿态到预抓取姿态的规划可行性；
2. 规划路径长度和预计执行时间；
3. 与关节软件边界的余量；
4. 预抓取后短距离接近的笛卡尔路径完成比例。

第一版可采用“按固定顺序尝试、首个完整可行者胜出”实现；诊断仍需输出每个失败候选的具体原因。待至少一次实体抓取成功后，再将路径长度和边界余量纳入显式评分。

## 状态机与数据流

```text
GRASP_READY + 新鲜稳定 RGB-D 目标
  → 打开夹爪
  → 对每个候选：构建预抓取位姿
       → 预抓取规划
       → 预抓取轨迹反馈确认
       → 短距离笛卡尔接近规划与反馈确认
  → 首个成功候选
  → 闭合夹爪并确认夹爪位置发生变化
  → 小幅抬升并确认轨迹反馈
  → HOLDING
```

若某候选的 IK、普通规划、笛卡尔接近或反馈确认失败，保持夹爪张开，记录原因并尝试下一个候选。所有候选均失败时停止在当前位置，发布 `ALL_GRASP_CANDIDATES_FAILED`；不自动失能，不自动复位，不发起不受控搜索。

若抓取前目标失效或超出对齐误差，停止候选选择并请求视觉重新对齐。若夹爪闭合后抬升失败，保持夹爪闭合并发布保持状态，等待操作者处理。

## 碰撞场景边界

本阶段继续请求 MoveIt 规划和碰撞检查，不永久关闭碰撞检测。但粗略抓取的诊断必须区分：

- 无 IK / 超出关节范围；
- 目标姿态不可规划；
- 起始状态已与 Octomap 碰撞；
- 预抓取路径碰撞；
- 笛卡尔接近路径不足；
- PiPER 轨迹反馈未到位；
- 夹爪未产生位置反馈。

当所有候选均因 `<octomap>` 与同一机器人连杆碰撞而失败时，报告 `PLANNING_SCENE_BLOCKED`，不得把它伪装成“目标不可抓取”。机器人自体点云过滤、桌面/支架显式建模和规划场景时效恢复属于后续工作，详见 `docs/purple_cube_real_arm_roadmap.md`。

## 参数与诊断

新增或明确的配置应包括：启用的候选名称及顺序、每个候选的预抓取退距/净空、接近距离、接近速度、最小笛卡尔路径完成比例和抬升距离。第一版复用当前低速速度比例与轨迹反馈门限；任何参数改变必须通过 YAML，不将实体标定值散落到 C++ 源码中。

`/brain_robot_grasp/state` 应展示候选名称和阶段，例如 `CANDIDATE_DIAGONAL_LEFT_PREGRASP_PLANNING`。`/brain_robot_grasp/diagnostic` 应展示每个候选的拒绝理由与最终选择，例如 `CANDIDATE_REJECTED_TOP_DOWN_PLAN_FAILED`、`CANDIDATE_SELECTED_DIAGONAL_RIGHT`。

## 验收顺序

1. 不发布实体轨迹的条件下，验证三个候选均能构造目标位姿并输出诊断。
2. 只执行到预抓取，分别记录每个候选的 MoveIt 规划结果。
3. 对首个可行候选执行短距离接近，确认末端不穿过桌面或冲向电脑。
4. 验证开爪、闭爪及夹爪位置反馈。
5. 验证小幅抬升和轨迹终点反馈。
6. 在同一摆放位置重复三次；至少一次完成物体保持抬升。

成功编译、MoveIt 规划成功、PiPER 实际执行到位和实际方块被夹住分别记录，不能互相替代。

## 非目标

本阶段不实现完整动态抓取、目标移动预测、颜色候选重识别、连续再规划、点云自过滤修复、永久环境地图、人体环境测试或放置/搬运流程。
