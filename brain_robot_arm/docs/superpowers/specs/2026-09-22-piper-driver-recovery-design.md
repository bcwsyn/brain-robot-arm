# PiPER 驱动恢复设计

## 背景

机械臂在执行外部官方 SDK 示例后，ROS 驱动出现状态全零、关节控制不生效的问题。CAN 接口在 3 秒内持续收到约 9142 帧，因而 USB-CAN、物理总线和机械臂反馈链路均仍在工作。

仓库初始版本的 `piper_ctrl_single_node.py` 使用 `C_PiperInterface`。当前工作副本已切换为 `C_PiperInterface_V2`，且虚拟机安装的 Python 包为 `piper_sdk 0.6.2`。这两项变化使当前控制链路偏离了原先工作组合。

## 目标与边界

恢复原有 ROS 控制路径，使其与旧接口兼容；将 Python SDK 版本固定，避免 `pip install -U` 再次隐式改变运行行为。该工作不修改视觉、MoveIt、Servo、抓取规划、CAN 波特率或硬件接线。

## 方案

1. 将驱动入口恢复为仓库初始的 `C_PiperInterface` 路径，撤销为 V2 接口添加的模式控制与调试改动。
2. 在仓库中增加一个明确的 SDK 版本约束，选用 `piper_sdk==0.4.2`。这是仓库导入时已存在的、同时提供 `C_PiperInterface` 与 `C_PiperInterface_V2` 的稳定历史版本；不依赖当前无版本约束的 `pip install piper_sdk` 行为。
3. 在虚拟机中卸载当前 0.6.2 并安装固定版本，清理所有 PiPER 驱动进程后启动唯一一个驱动。
4. 先验证 `/joint_states` 的非零位置反馈、`/arm_status` 的真实状态变化和 J2 小幅受控运动；仅通过后才启动一键视觉流程。

## 验收标准

- 只有一个 `piper_single_ctrl` 进程。
- `/joint_states` 持续发布，且位置来自机械臂的真实反馈而非全零默认值。
- 使能服务和小幅 J2 命令能导致可观察的状态或位置变化。
- 未启动或改动视觉抓取控制栈。

## 风险与回退

如果固定版本后仍无法解析反馈，停止在底层驱动验证阶段，不进入视觉流程；保留当前 0.6.2 的版本信息以便可以显式回装。此时下一步是比较 0.4.2 与 0.6.2 的 CAN 解析差异，而不是修改机械臂运动参数。
